# ai-reply-helper（微信 AI 润色助手）

一个 **Windows 桌面助手**：在微信（或任意 App）输入框打字 → 按全局热键 →
自动读取最近聊天上下文 → 调用大模型生成多个润色版本 → 你选一个 → 自动回填并粘贴发送。

**为什么不是“微信插件”**：个人微信没有官方开放 API，逆向协议（WeChaty/iPad 协议）
违反微信 ToS、极易封号。本方案只使用「剪贴板 + Windows UI Automation」模拟用户自己操作，
合规、零封号风险，且不止微信能用（飞书、钉钉、浏览器都行）。

## 功能

- 全局热键唤起（默认 `Ctrl+Alt+P`；可在 `config.json` 改 `hotkey` 字段，已存在 config.json 直接改该文件）
- **点击右下角动图也能触发**，与按热键完全等价：直接用鼠标点一下 1.webp 动态图标即可
- **设置页（提示词 + 模型与 Key + 软件作者）**：**按下鼠标中键（滚轮按下）** 任意位置即可打开
  （CodeBuddy 风格深色窗口，三个页签，**默认停在「软件作者」页**，
  左列表 / 左说明 + 右内容的布局）：
  - **提示词页签**：查看 / 新增 / 编辑 / 保存 / 删除提示词，内置项可**恢复默认**，
    点「设为生效」即时切换（无需重启）；顶部状态条显示当前生效项与总数
  - **模型与 Key 页签**：**多套模型配置分别管理**（名称 / API 地址 / 模型名 / Key），
    可新增、删除、切换生效；Key 默认**打码显示**，点「显示」才展开，可一键**测试连接**
  - **软件作者页签**：展示**使用交流群**与**作者微信公众号**两张二维码卡片，
    并提供一键放大与「加入交流群 / 作者公众号」按钮；
    二维码随窗口尺寸自适应重绘（限制最大边长），点击即可放大查看
  - 所有操作都有明确的成功 / 失败提示（底栏文字，不弹窗打断）；删除这类不可逆操作才二次确认
  - 字段必填、地址格式等均做校验，不合格的输入框会**标红**并给出原因
- 捕获当前输入框草稿（不破坏原内容）
- 输入框为空 → 自动切换为「依据聊天上下文草拟回复」模式，直接替你写一条可发的回复
- 尽力读取微信当前聊天最近 5 条消息作为上下文（读不到则自动降级，不影响润色）
  - **微信 3.x**：走 UI Automation 直读消息列表，文字精确（与旧版行为完全一致）
  - **微信 4.x**：界面不向系统暴露控件，改用 **WGC 窗口捕获 + 像素锚点定位 + OCR** 读消息区
    （被遮挡也能截、不抢前台、窗口任意缩放都能对准；取不到时再回落截屏 OCR）
- 调用 DeepSeek（OpenAI 兼容接口）生成多个版本话术
- 浮动窗展示，点「发送」回填并 `Ctrl+V` 粘贴，点「复制」仅复制
- **右下角状态动图**（需 `1.webp` / `2.webp`）：程序启动显示 1.webp，按热键后切到
  2.webp，关闭「优化后语句」弹窗后切回 1.webp，直观提示当前状态
- **图标可拖动**：按住右下角动图**拖到任意位置**，松手即生效并**记住位置**（写入
  `config.json` 的 `tray_pos`，下次启动沿用）。拖动全程被限制在屏幕可视区内，
  不会拖出屏幕；若保存的位置越界或失效，会自动**复位到右下角**。
  拖动**不会**触发润色——只有「按下后几乎没移动」才算点击
- **优雅退出**：把鼠标移到右下角动图上**悬停**，右上角会浮现一个红色 **×** 按钮，
  点击即退出程序（鼠标移开后 × 自动隐藏）

## 安装

```bash
cd wechat-ai-polish
python -m pip install -r requirements.txt
```

## 配置 API Key（二选一）

1. 环境变量（推荐，避免把 Key 写进文件）：
   ```bash
   set AI_API_KEY=sk-你的deepseek_key
   ```
2. 或复制 `config.example.json` 为 `config.json` 并填入 `api_key`。

> 已适配任意 OpenAI 兼容接口：改 `api_base` / `model` 即可切到豆包、GPT 等。

## 运行

```bash
python main.py
```
或双击 `run.bat`。启动后保持后台运行，在微信输入框打字，按热键即可。

## 使用流程

1. 在微信输入框写好草稿（不用发）。
2. 按 `Ctrl+Alt+P`。
3. 助手捕获草稿 + 最近聊天上下文，调用 AI 生成 3 个版本。
4. 弹出小窗：选「发送」即回填微信输入框并粘贴（你再按微信的发送键）；
   选「复制」则只复制文本自己处理。

## 说明与边界

- **获取微信内容有等待宽限期**：触发后会持续轮询等待微信窗口（默认最长 **10 秒**，
  可在 `config.json` 改 `grab_timeout`）。期间你随时可以打开微信、进入聊天窗口、写好草稿，
  一旦检测到就**立即**抓取，不会傻等到 10 秒；只有超过 10 秒仍拿不到内容，才会弹出提示框。
  抓取过程中的瞬时失败（如微信刚启动、UIA 未就绪）会在预算内自动重试，不会过早报错。
- **微信上下文读取是 best-effort，按版本自动分流，两条路径互不干扰**：读取上下文只有一个入口，
  内部按「运行时能力探测」判断走哪条，**不做版本号硬判断**：
  1. **3.x 路径（UIA 直读）** —— 微信 3.x（Duilib）的消息列表是 ListControl，文字由系统精确给出、
     没有识别误差。**命中即返回，永远不会进入 4.x 的采集代码**；另含「控件树扁平收集」兜底，
     服务于少数控件树是扁平的过渡版本。
  2. **4.x 路径（WGC 采集）** —— 微信 4.x（Qt 重写）完全不向 UIA 暴露控件，只能截图。用
     **Windows Graphics Capture 直接抓窗口**（**被遮挡、不在前台都能截**，且不抢焦点、不打断打字），
     消息区靠**像素锚点**动态定位（认面板底色与分隔线，不写死坐标、深浅主题通用），
     先等画面停稳再识别，最后按气泡颜色区分「我 / 对方」并丢掉时间戳、图片里的字。
  3. **兜底** —— WGC 不可用（依赖缺失）或抓帧失败时，回落到原有的「截屏 OCR」。

  `config.json` 的 `capture_4x`（默认 `wgc`）可切回 `ocr`；`ocr_context`（默认 `true`）关掉则
  4.x 完全不读上下文（只保留 3.x 的 UIA 路径）。
- **4.x 的识别误差与前置条件**：两条 4.x 后端都基于图像识别，**存在固有误差**
  （如「消息」可能识别成「消，」），上下文仅用于让模型了解语境，不必逐字精确；
  若需精确文本，可手动把对方的话粘进输入框。
  系统侧需要「设置 → 时间和语言 → 语言 → 中文 → 可选功能」中的**「光学字符识别」**，
  程序已强制优先创建中文识别引擎（否则系统默认英文引擎会让中文全部丢失）。
- **回填依赖焦点还原**：触发热键时光标需在微信输入框内；发送时会把焦点还给微信再粘贴。
- **tkinter 弹窗**由热键回调线程拉起，Windows 下单实例通常正常；若遇到 Tcl 初始化问题，
  可改为在主线程用队列派发（后续增强）。
- **COM 初始化已处理**：pynput 热键回调运行在子线程，使用 uiautomation 前已在
  `main.py` 用 `UIAutomationInitializerInThread` 初始化 COM 单元。若仍出现
  `尚未调用 CoInitialize / Can not load UIAutomationCore.dll`，多为 uiautomation 过旧，
  执行 `pip install -U uiautomation` 即可。
- **失败可见**：AI 调用失败（如 401 Key 无效 / 网络错误）会弹出置顶错误提示窗，
  不再静默无反应；具体原因同时写入 `polish.log`。
- **热键不要用 Space**：空格是中文输入法确认候选字的最高频键，`Ctrl+Alt+Space`
  会在正常打字（按空格确认）时频繁被误触发。已默认改为 `Ctrl+Alt+P`；
  想更省事可用功能键 `F8`（在 config.json 把 `hotkey` 改成 `f8` 即可）。
- **热键格式注意**：`config.json` 里普通字符必须裸写（如 `p`、`k`、`f8`），
  **不要**写成 `<p>`。早期版本把普通字符也用 `<>` 包裹，导致启动即报
  `ValueError: <p>`（pynput 把 `<p>` 当 Key 枚举查找失败）。当前 `_hotkey_to_pynput`
  已修复：仅修饰键（`ctrl/alt/shift/cmd/space`）包裹 `<>`，其余原样输出。
- **配置页触发方式**：按 `Ctrl+Alt+E` 会与微信 `Ctrl+Alt+W/A/S/D/Q`（打开/截图系列）及
  Windows 放大镜 `Ctrl+Alt+F`（全屏视图）冲突，**已改为「鼠标中键（滚轮按下）」全局触发**，
  任意位置按中键即开配置页。比键盘组合更不易误触，也不再占用任何系统/微信快捷键。
- 日志全部写入 `polish.log`，便于排查微信读取 / API 调用问题。
- **右下角动图（Windows）**：用 `tray_widget.py` 做一个无边框、置顶、透明背景的
  窗口钉在屏幕右下角，播放 `1.webp`（空闲）/ `2.webp`（处理中）。webp 带透明通道，
  用「键色合成 + `-transparentcolor`」实现透明窗口（仅 Windows 生效，其他平台会
  显示品红色底，不影响逻辑）。动图帧很多（约 120 帧），已做「分块解码 + 抽帧」，
  启动即出窗口、首帧很快、不卡主流程。相关配置项：`idle_gif` / `active_gif` /
  `tray_size`（默认 220 像素）/ `tray_pos`（拖动后的位置，默认 `null` = 右下角）。
- **拖动与点击如何区分（避免误触）**：采用「按下 — 移动 — 抬起」三段判定，
  位移超过 4px 才算拖动；只移动时**不触发**润色，只有位移在阈值内的短按才触发。
  拖动过程中会把窗口夹进可见区域（优先用系统工作区，**不会压住任务栏**），
  并被限制在主屏范围内。位置用「自己下发的坐标」记录而非 `winfo_x()`——
  后者是 Tk 缓存的几何值，连续移动事件中可能滞后，会存到拖动前的位置。

## 设置页说明（提示词 / 模型与 Key / 软件作者）

打开方式：任意位置**按下鼠标中键（滚轮按下）**；打开后**默认停在「软件作者」页**
（使用交流群 / 作者公众号二维码），其余页签点顶部标题切换；`Esc` 关闭，`Ctrl+S` 保存当前页签。

### 提示词页签
- 左栏列出全部提示词（`内置` / `自定义` 徽章 + `✓ 生效` 标记），点一条即在右栏编辑。
- **保存**：写入 `config.json` 的 `prompts`。（新增后需再点「设为生效」才会真正使用。）
- **恢复默认**：把内置提示词还原为出厂内容（仅内置项可用）。
- **设为生效**：切换当前使用的 system 提示词，下一次润色即生效。
- **删除**：仅自定义项可删（内置项阻止删除，避免删掉后无法恢复）。

### 模型与 Key 页签
- 支持**多套模型配置**分别管理：适合「DeepSeek 日常用 + 豆包备用」这类场景。
- 每条配置独立保存 **API 地址 / 模型名 / API Key**；点「设为生效」后立即用于后续调用。
- **Key 默认打码**（`sk-••••••••abcd`），点「显示」才展开；列表与所有提示语一律只显示脱敏形式。
- **测试连接**：用 `max_tokens=1` 的最小请求验证 Key 是否可用（几乎不产生费用），
  网络请求在子线程执行，不会卡住界面。
- 至少要保留一条模型配置（最后一条不允许删除）；要把某条停用，直接清空它的 Key 即可。

### 软件作者页签
- 左栏：作者信息与引导文案（交流用法 / 反馈问题 / 获取更新），底部是
  「加入交流群 / 作者公众号」两个入口按钮；
  右栏：**使用交流群**与**作者微信公众号**两张二维码卡片并排，均用白底保证扫码对比度。
- 每张卡片随窗口尺寸**自适应重绘**并限制最大边长（300px）——小屏能扫、大屏不糊；
  **点击二维码**或点「点击放大」按钮可弹出大图窗口。

### 二维码入口与资源
- 除页签外，底栏右侧另有「**作者微信公众号 ｜ 使用交流群**」两个快捷入口
  （位于「关闭」按钮左侧）。
- **悬停**：延迟约 0.4 秒浮出二维码小预览（类似 tooltip，鼠标扫过不会闪）；
  **点击**：弹出大图窗口，便于扫码。
- 弹窗内的二维码会随窗口尺寸**重新渲染**（保持宽高比 + LANCZOS 重采样），
  放大后依旧清晰可扫；初始大小按屏幕比例与图片比例计算（长边夹在 `[280, 460]`），
  竖版长图也按高度换算，不裁切、不拉伸。`Esc` 关闭。
- 资源文件：`author_qrcode.png`（作者公众号）、`group_qrcode.png`（使用交流群），
  `build.spec` 均已计入打包资源。**文件缺失时对应入口/按钮自动隐藏**，
  卡片内会写明缺了哪个文件，不会留下点了没反应的死链接。
- 群二维码由微信生成，**自带约 7 天有效期**。过期后把新的群二维码裁成正方形、
  命名为 `group_qrcode.png` 放到程序目录即可（外部同名文件优先于打包内置资源），
  界面无需改动。

> **安全提示**：按当前约定，API Key 以**明文**保存在 `config.json` 里 —— 这个文件本身就是凭据。
> 界面会打码显示、也不会把 Key 写进日志，但请**不要**把它发给别人或上传网盘。
> 分发与备份请避开该文件（`build.spec` 与 `.gitignore` 已排除）；
> 更保密的做法是用环境变量 `AI_API_KEY`（优先级高于配置文件）。

## 查看实时日志

启动后（`run.bat` 或 `python main.py`）：

- **控制台窗口实时滚动**（默认开启，设为 `console_log: false` 可关闭）：按热键后可直接在窗口看到完整流程，包括
  - 发给大模型的**完整提示词**：`system` 角色设定 + `user` 草稿/上下文
  - 大模型的**响应原文**、状态码、耗时、Token 用量
  - 最终解析出的版本数
- **日志文件**：同样内容实时写入 `polish.log`（UTF-8），可用记事本 / VS Code 打开。

相关配置项（`config.json`）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `console_log` | `true` | 是否在控制台窗口实时输出日志；`false` 则只写文件 |
| `log_prompt` | `true` | 是否记录完整提示词与响应原文；`false` 则只记录摘要（模型/耗时/版本数） |
| `ocr_context` | `true` | 微信 4.x 是否允许用 OCR 读聊天上下文；`false` 则 4.x 不读上下文（只保留 3.x 的 UIA 路径） |
| `capture_4x` | `wgc` | 微信 4.x 的采集后端：`wgc` = WGC 窗口捕获（推荐，被遮挡也能截、不抢前台）；`ocr` = 旧截屏方式（需窗口在前台且不被遮挡） |
| `grab_timeout` | `10` | 触发后等待/重试获取微信内容的最长秒数，超时才弹提示框 |
| `context_messages` | `5` | 读取最近多少条消息作为上下文 |

> 日志**不会**记录 API Key（请求头不落盘），可放心查看。

## 文件结构

```
config.py          配置加载（config.json + 环境变量）
ai_client.py       大模型调用（DeepSeek，多版本，JSON 解析）
wechat_window.py   微信窗口/输入框/消息列表统一定位（兼容 3.x 与 4.x）
capture_wgc.py     微信 4.x 采集：WGC 抓窗口 + 像素锚点定位消息区 + 说话人分类
ocr_reader.py      Windows 内置 OCR（带坐标识别）+ 旧截屏读取路径
capturer.py        读取微信最近消息：3.x 走 UIA 直读、4.x 走 WGC，最后兜底截屏 OCR
paste_back.py      剪贴板还原 + 焦点还原 + Ctrl+V 回填
ui.py              tkinter 浮动确认窗
tray_widget.py     右下角状态动图（1.webp / 2.webp，线程安全）
main.py            全局热键编排主流程
paths.py           统一路径管理（区分只读资源/可写数据，兼容打包）
first_run.py       首次运行引导（填写 API Key + 测试连接）
build.spec         PyInstaller 打包配置（单文件 GUI exe）
build.bat          一键构建（PyInstaller → Inno Setup）
installer.iss      Inno Setup 安装脚本（免 UAC、开始菜单、卸载入口）
使用说明-给朋友.md  分发给朋友的使用说明
tests/             单元测试（无需网络即可运行）
```

脚本依次执行：装/升级 PyInstaller → `pyinstaller build.spec --noconfirm --clean` → `ISCC installer.iss`。

### 关键设计

- **路径分流**（`paths.py`）：只读资源（`1.webp`/`2.webp`）打进 exe，从 `sys._MEIPASS` 读；
  可写数据（`config.json`/`polish.log`/单实例锁）写到 `%LOCALAPPDATA%\ai-reply-helper`，
  避免「单文件临时目录丢配置」和「Program Files 无写权限崩溃」两个大坑。
- **不内置任何 API Key**：`config.json`（含作者真实 Key）与 `config - *.json`（私人场景）**一律不打进包**。
  朋友首次运行会看到引导窗口，填写**自己的** Key（附申请指引与「测试连接」）。
- **`--noconsole`**：无黑框。注意 `main.py` 已对 `sys.stdout is None` 做判空处理。
- 安装到 `{localappdata}\Programs\ai-reply-helper`，**免管理员(UAC)提权**。

### 已知事项

- **图标必须是真正的 ICO**：`icon.ico` 同时被 PyInstaller（exe 图标）和 Inno Setup
  （`SetupIconFile`）使用。Inno 只接受真 ICO，且受 `Setup.e32` 资源段大小限制 ——
  若把 PNG 直接改名成 `.ico`（或塞入超大图），会出现
  `Resource update error: File is too large`，PyInstaller 那步却看不出问题。
  当前为 7 个尺寸（16/24/32/48/64/128/256）的真 ICO、约 115KB；
  原始高分辨率图保留在 `icon_source.png`，换图标时用它重新生成：
  `Image.open("icon_source.png").convert("RGBA").save("icon.ico", format="ICO", sizes=[(16,16),…])`。
- **`build.bat` 必须保持纯 ASCII**：cmd 解析 UTF-8 中文注释时会吞掉 `rem` 关键字，
  报 `'…' is not recognized as an internal or external command`（`chcp 65001` 也救不了）。
- **杀软误报**：PyInstaller 单文件常被 Defender 误报（无代码签名）。让朋友选择「允许 / 添加信任」即可。
- **体积**：当前约 42MB。若想瘦身，可把 `1.webp`/`2.webp` 预压到 220px、约 40 帧（可省约 7MB），
  托盘原本就是按 220px 显示并抽帧的，画质影响很小。
- 目标平台：**Windows 10/11 64 位**（程序依赖 `uiautomation` 与 Windows `user32` API，不支持 macOS/Linux）。
- 业务前提：朋友电脑需安装**微信 PC 版**并登录。
